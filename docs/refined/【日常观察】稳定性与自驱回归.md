更新：2026-10-12。用户决定将长期观测项转为日常使用观察，不增加云端自检调用。此文件记录观察责任和反馈方式，不将未测项目改为正式通过。

| 日常观察项 | 使用中关注什么 | 当前证据边界 |
|---|---|---|
| 在场退避 / 离场波动唤醒 | 连续聊天时是否过密打扰；离场后是否恢复自驱；升级或重启后是否突然重复报点 | A10c定向规则与跨进程期限/档位测试；连续多日和有效Doze仍属日常观察 |
| 自动任务与后台保活 | 到期是否执行；锁屏、网络恢复和升级后是否漏执行或重复执行 | 宿主与真实Room排期测试不等于全部真实模型任务已执行 |
| 动态模块 / QQ | 间歇启动失败、状态与挂载不一致、持续高CPU、异常发热耗电 | 当前运行/挂载核对与历史修订证据；长期资源风险持续观察 |
| 记忆与知识库 | 模板污染是否再现；更正、否定要求和来源是否正确；答案是否全面 | 固定基准和个人最小样本限定通过，不由模型自评补齐个人真值 |

## 记录与反馈

发现异常时记录时间、页面、预期与实际、是否锁屏/前台、网络状况和是否刚升级。可附错误提示或截图；无需提交密钥或完整私人对话。没有异常无需定时反馈，也没有新增观察天数硬门槛。

Zero现有本地运行日志可用于事后按需核对；本轮未实现或启用新的自动告警、云端自检、模型总结或定时巡检。用户手动使用现有功能产生的正常请求不属于新增开发自检。

## 仍由开发完成的独立门

- 跨进程恢复、取消/迟到保护、UI页面证据及最终交付核对，继续按验收计划推进。

- 全页证据关联不替代未覆盖的真实分屏、系统权限或进程死亡验收。
