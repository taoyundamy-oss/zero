# 独立召回基准 v1

## 验收决策（2026-10-02，用户已确认）

日常向量晋升采用固定独立基准加候选完整性检查；个人记忆/知识库抽样单独验收，不作为每次自动晋升的人工前置条件。

## 固定数据与口径

- 唯一数据源：services/src/main/java/com/zero/v2/services/embedding/VectorRecallBenchmark.kt。
- 数据集版本：zero-independent-recall-v1。12条明确标注的独立文本、6个独立问题；不是用户资料，也不是从候选正文生成的自查询。
- SOURCE：备份验证、设备报修；NEGATION：禁止删除数据、断网保留进度；CORRECTION：更正培训地点、调整备份时刻。每题一个相关来源、一个明确禁止来源，其余文本也参与排序。
- 使用实际embedding provider，文档走Memory/Knowledge各自输入模板，查询走原始独立问题。完整12文档+6查询产生真实向量后，全量余弦排序计算Recall@1。
- 来源/否定/纠正每类Recall至少0.9，总体与分类均不得低于同数据集既有报告；禁止来源命中必须为0。每类2题，因此v1实际上要求每题命中，不因实际provider结果降低阈值。
- 数据摘要绑定文本、标题/标题链、标签、问题、K、阈值及域；完整报告绑定候选摘要/空间/基线。任何数据集变更必须显式版本升级和基线迁移，不能静默重置分数。

## 发布与成本边界

- 生产Hilt注入VectorBenchmarkGate；build完成候选后自动评估，合格才走approve和publishValidated。源条目/数量/候选字节在事务中重新核对。
- 基准不会写入个人Memory/Knowledge来源表。固定基准只能证明这份小样本的质量，不代表个人资料召回或A4规模/延迟达标。
- 同一候选已拒绝结果落盘后不重复请求；新候选会重新评估，每次18条短文本输入（远端provider按其批次限制拆请求）。并未实现跨候选分数复用，不能宣称零额外成本。
- 请求超时/异常不审批，保留候选并用已有30分钟重试机制；取消透传。空间改变不混用。仅保留每域最近一次报告，128KiB上限、AtomicFile、noBackup目录，不含查询正文或密钥。
- 报告published字段是写入时观察值；读取入口附加currentlyActive，以Room当前指针为准，避免提交后报告写失败/进程终止造成误报当前状态。
- kb_status展示独立基准/资料抽样、Recall、样本数、通过/拒绝和是否当前启用；不新增设置入口，不改工具schema。

## 个人资料抽样

VectorRecallDataset支持固定标签绑定来源文本/标题/标题链的SHA256，重建只更换UUID时可以重新关联。内容修改/删除、重复内容导致歧义均拒绝；不模糊匹配，不自动编造标签。当前个人抽样入口evaluateAndPublish仍是显式开发接口，不作为独立基准已发布版本的无条件替换。两种数据集不一致时审批层拒绝；后续个人抽样应使用独立报告/复核流程，不能覆盖固定发布基线。
