## 版本 A：完整启动（首次会话 / 中断后恢复）

```
你正在开发 Zero V2 收束阶段（S 轨），一个 Android AI Agent 应用及其云服后端。项目位于 D:\ZeroV2。

## 第一步：加载上下文（只读，不修改任何文件）

请依次读取以下文件，了解本阶段全貌：

1. `D:\ZeroV2\docs\refined\ZeroV2-收束落地实施计划.md` — 实施计划与进度追踪（§九 进度表 = 当前位置权威）
2. `D:\ZeroV2\docs\refined\ZeroV2-收束开发设计.md` — 设计决策（D115-D126 · 用户裁定基线 · 〇章问题意见映射表）
3. `D:\ZeroV2\docs\refined\CLAUDE_CODE_PROMPT_SHOUSHU.md` — 本提示词（行为边界）

根据落地实施计划 §九 进度表中第一个 ⏳ 状态的 Step，精读该 Step 的完整定义（文件清单/验证标准/关联 SR-C-G 条目）。

## 第二步：执行当前 Step

严格按落地实施计划中该 Step 的定义执行：
- 只创建/修改该 Step 明确列出的文件
- 不改动 Step 范围外的任何文件与功能
- 每个 Step 自带验证标准——逐条对照，不达标的验证项如实标注"待实测/待用户"

## 修改权限边界（硬性，违反即回滚）

Claude Code 只允许做三类修改：
1. 实现已批准设计（收束设计文档 D115-D126 及落地计划对应 Step）
2. 修复落地计划 SR/C/G 三层验证表明确列出的问题
3. 修复实现过程中发现的真实 bug（有错误日志/复现证据）

Claude Code 不允许做三类修改：
1. 未授权架构重构（模块边界/通信机制/数据层的结构性变更）
2. 将已裁定的方案重新设计（D 决策与用户裁定基线——如：设置不大改、三 tab 固定、
   执行轨迹单一折叠卡、系统气泡右侧渲染、AUTO 权限让渡、原地增强 SystemEventModule）
3. 因"实现更简单"而修改模块边界、通信机制或 UI 基线

遇到边界拿不准时：记录问题 + 向用户提问，不自作主张。

## 行为规则

1. **每次只做一个 Step**。完成后停下，构建验证，等用户确认再推进。
2. **Android ≤3 文件/Step；云服 ≤1 逻辑单元/Step**。超出即拆子步骤（迁移例外：Room 迁移文件组同 commit）。
3. **构建验证**：Android 改动后运行 `cmd //c "D:\ZeroV2\_build_apk.bat"`；云服改动后
   docker compose rebuild + curl 验证 + 回归 `bash scripts/test_mcp.sh`（9 用例全过才算完成）。
4. **先读后写**。修改现有文件前必须 Read 确认当前内容；核心文件（ChatBotModule/
   McpClientModule/TriggerHub/ChatViewModel）改动前精读相关段。
5. **参考标杆**：FC → WebSearchModule；Room+迁移 → MemoryModule/MIGRATION_12_13 先例（X9）；
   模块详情页 → ModuleDetailScreen；Provider 抽象 → gateway/tools/wechat.py D97 缝；
   云服任务 → worker/tasks/ 既有模式（update_meta/幂等/file_id 登记）。
6. **埋 AgentTrace**：每个关键集成点 record 一句；**静默失败路径必须留 trace**（E28 铁律）。
7. **教训遵循**：开发前扫读落地计划关联的 E 教训（如 SR2→X9、S10→E14/C7、S11→G1/G11）。
8. **真实偏差入档**：执行中发现设计与现实不符（如新端点/新权限行为），先实测取证，
   记入 E 教训表并同步两文档，再继续——不静默偏航。

## 第三步：输出标准格式

### Step Sx.y 完成：[名称]

**改动文件**：
- 新增: path/to/File（N 行）
- 修改: path/to/File（变化简述）

**验证结果**：
- [x] Build 通过 / APK 时间戳 / 回归 9/9（云服）
- [x] 该 Step 验证项（逐条，实测数据）
- [ ] 待用户 L3 实测项（如有，写明操作）

**执行偏差**（如有）：与计划的差异 + 原因 + 已入档位置

## 第四步：更新状态

修改 `ZeroV2-收束落地实施计划.md` §九 进度表：
- 该 Step ⏳→✅ + 验证摘要
- 发现的新问题 → 追加到对应验证表（新 E/G 编号）
- 用 git commit 留痕（信息含 Step 号与关键结论）

---

不确定的实现选择：先查设计文档对应 D 决策 → 再查落地计划 SR/C/G 表 → 都没有 → 向我提问。
```
