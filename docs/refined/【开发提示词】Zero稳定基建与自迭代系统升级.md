## 主提示词

你是 Zero 项目的主开发 Agent。请在 `D:\ZeroV2` 基于当前稳定运行系统，按已确定的设计完成本轮升级开发。直接执行代码审查、实现、必要测试、清理和文档更新；不要只输出计划，也不要每做完一个步骤就询问是否继续。

### 一、首先理解最终目标

本轮交付一个基建稳定、接口统一、LLM 能感知系统并自主编排、能在 Termux 动态模块区受控自迭代的个人 Android 助手。此次开发同时完成旧设计残留清理、多模态主路径、记忆与知识库升级、动态角色表达及 UI 重构。

这是保留当前可靠能力和用户数据的升级开发。最终生产路径要统一，已替代实现要退役；不能只加接口包装、继续保留旧新两套状态/调用路径，也不能用从零重建、清库或重装替代迁移。

目标设备是 Samsung Galaxy Z Fold3，12 GB RAM / 256 GB 存储。整机 RAM 不等于应用内存预算。不新增大文件本地 LLM、embedding 或 reranker，不引入跨设备运行依赖。云端模型优先 DeepSeek、Qwen 等中国模型生态，保留用户自定义 profile；实际模型能力、端点、协议和窗口以当前官方资料与实测为准。

注意区分两个角色：你作为开发 Agent，可以修改 Android/Kotlin/Python/数据库迁移等项目源码以完成本次开发；最终产品中的运行时 LLM，只允许在规定的 Termux 动态模块区自迭代，不能改写 APK、宿主权限策略、数据库 schema、凭据、supervisor 或 SDK。

### 三、不得重新讨论的已定决策

- 稳定Android宿主管理生命周期、权限、预算、凭据、数据和统一状态；生产工具调用走统一Dispatcher，模块跨域调用遵守safeCall，Hilt/Bus解耦。
- 低风险Termux模块允许自动生成、验证、灰度与晋升；新增权限、删除用户数据、不可逆数据迁移、基建修改及无法证明低风险的候选只产提案。
- 该发布策略仅约束动态模块自迭代，不恢复全体普通工具已退役的AUTO/CONFIRM/FORBIDDEN确认流程。
- 多模态优先使用已配置、确实支持相应输入的云端原生能力；缺能力时回退已有Vision/ASR等Adapter。
- 98%指稳定前缀的提供商缓存目标；按设计的可观测性和统计口径报告，不承诺整段输入98%命中，不将估算当精确值，不删除零命中/失效样本来提高指标。
- Memory/Knowledge默认按相关性少量注入，可分别关闭；长期记忆仅保存有来源、可复核的文本事实与偏好，图/音频先转写再受同样规则约束。
- 亲密度按角色长期保存，情绪按会话短期变化；用户可查看、关闭表达影响、分别重置。动态角色只影响表达，不影响权限、事实、工具或系统规则。
- UI以对话为核心，资料/工作区/设置统一组织；采用已生成的Zero标识和视觉素材，结合现代Android规范。保留音乐、日历、文件等已有能力的可达入口。

### 四、开工与持续推进方式

先查看工作树、分支、已有暂存区、最近提交及实际进度。当前仓库可能有大量未提交改动，不得reset、clean、恢复覆盖或批量格式化；不要把原有改动归为自己的成果。

从总纲顺序中**第一个尚未通过验收的切片**开始。若已有实现，先核对接线、测试和遗留路径，只完成差额，不重复造实现。初次执行预计从B0开始，但必须以现场状态验证。

严格按以下顺序，每次完成一个切片：

`B0 → B1 → F1 → F2 → S1 → C1 → M1 → M2 → M3 → C2 → R1 → R2 → R3 → E1 → E2 → E3 → P1 → P2 → P3 → U1 → U2 → U3 → M4 → C3 → Z1 → I1`

每片循环：

1. 核对目标、依赖、当前caller、数据流和验收条件，简述本片修改范围。
2. 实施最小完整纵切片：接口、实现、生产接线、迁移、针对行为的测试必须配齐；不以空实现、固定成功返回或仅mock接线交付。
3. 检查旧路径：登记替代关系、消费者、删除条件。已无消费者且兼容职责已完成的旧实现应删除；依赖尚未迁移时写明在哪一片退役。
4. 运行受影响的测试与编译；读取失败输出并自主诊断修复，不靠删除测试、放宽断言、跳过守卫或改测试基准掩盖失败。
5. 更新本轮进度/清理台账/偏移记录，列明具体证据和未验证边界。编译失败或本片必需门禁未通过不能标完成。
6. 遵循项目提交规则，条件允许时一片一提交。仅提交本片可明确归属的变更，禁止`git add -A`夹带他人改动；无法安全分离已有改动时记录原因，不破坏暂存区。未经明确授权不push、发布或部署到外部环境。
7. 通过后继续下一片，不重复询问“是否继续”。遇到真实外部阻塞则记录并推进依赖允许的独立工作；不能跳过阻塞的验收并宣称总体完成。

### 五、各主线必须落实的工程要求

**B/F/Z：稳定升级与框架收口。** 冻结关键用户流、数据恢复与功能入口基线；统一生命周期、注册、调用、取消、错误、预算和配置路径。迁移services/framework对manager具体实现的依赖，避免循环依赖。新增模块仅需实现契约、元数据/配置/工具声明、Hilt绑定与契约测试，不应修改ChatBot/UI分支。迁移适配器须有明确退役任务，Z1完成生产caller收口和旧路径删除；真实外部协议兼容可保留，但须说明消费者和用途。核查旧cloud/IM路径可达性后再清理，不按关键字批量删除。

**S：系统感知。** 建立SystemStateRepository投影已有owner的事实，UI与LLM同源。zero_status支持分区、revision、分页、unknown/stale、观察时间；每轮只注入预算内必要摘要，详情按需读取。动作执行前重新校验源状态。禁止泄露Key/媒体载荷/私有正文，禁止查询状态隐式触发安装或付费推理；状态事件合并去抖，不制造LLM唤醒风暴。

**M/C：多模态与上下文。** ContentPart贯穿输入、历史、provider序列化与工具媒体引用；保留原始用户正文与媒体来源。附件做大小/尺寸/授权/生命周期管理，base64不进Room/Trace。profile真实能力路由，错误可解释并有受控回退。固定人设/协议构成稳定前缀；系统状态、摘要、RAG、情绪进入可变上下文。工具有界发现、确定性排序，不再默认全量；裁剪保留工具调用闭环，不截坏schema。缓存稳定性、总token预算与用户体验同时验收。

**R：记忆/知识库。** 区分长期事实、用户图谱、会话摘要、知识chunk的语义和所有者；提取队列持久化、幂等、可恢复。检索有界但不能只用词面预筛牺牲纯语义召回；固定中文/数字/否定/纠错/时效/删除样本对比Recall@K、引用准确性、误注入、P95与内存。embeddingSpaceId包含模型/维度/归一化/切块等版本；影子索引验证后切换，失败保留可用索引；删数据不能被旧任务/索引复活。模型和索引均可替换，新增native依赖要有瓶颈证据和Android兼容验证。

**E：受控自迭代。** staging与active分离，编译/探活失败不能覆盖健康源码。按版本固定依赖，禁止改变全局pip环境；SDK/manifest版本化；部署journal、幂等、锁、恢复与活动指针统一。低风险判定必须可强制执行：venv/proot、静态扫描、LLM评分和探活均不等于权限隔离。同UID任意Python若无法阻止越界访问，应降为提案，不能先运行危险测试再判断风险。受限执行器未证明有效前，仅开放可信runner中的声明式模块自动执行。灰度限次数/时长，失败停止路由并回退；代码回退不能冒充副作用撤销。保留独立紧急停止，禁止运行时LLM改守卫/测试判定/预算使自身通过。

**P：动态角色。** 固定人设不被状态覆写；角色长期关系与会话短期情绪分开持久化，事件有来源/幂等/限速/衰减。失败不阻断固定人设回复；UI查看/重置完整，动态风格不污染稳定前缀。

**U：UI重构。** 使用已有素材作为设计源，以原生Compose接线，不把HTML预览塞进WebView交付。统一Theme/tokens/基础组件；完成对话、资料、工作区、设置与旧功能入口映射。依据窗口大小/折叠姿态布局，支持IME/insets、predictive back、动态色、深浅色、48dp触控、字体200%、TalkBack与减少动态。处理动效仅可见且活动时播放，流式token不反复动画。实现adaptive/monochrome/legacy图标资源；参考图中的状态是样例，正式UI必须绑定真实系统状态。升级依赖使用经兼容验证的稳定版本，不直接追alpha。

### 六、数据、安全和验证底线

遵守`ModuleLifecycleManager.safeCall()`、Room的Mutex与事务、MessagePipeline总3秒和IMessageFilter 100ms契约。耗时LLM/检索/索引工作不得放进filter主路径；遵守协程取消，避免宽catch吞取消。权限/参数校验保留在执行端，不能只靠提示词。

读取当前Room版本后分配下一个migration，不能照文档旧v22重复占用版本。schema导出、旧库数据保留与迁移测试必需；禁止destructive fallback、清库或使用真实用户数据做不可逆试验。跨版本回退设计要考虑数据库兼容，不用降版本APK冒充数据库回滚。

每片执行受影响模块的行为测试和`:app:assembleDebug`或适当子项目编译，阶段收口执行仓库`qualityCheck`。测试优先覆盖真实外部行为、失败/取消/并发/恢复；避免仅复述实现的测试。已有环境曾使用：

```powershell
$env:JAVA_HOME = 'C:\Program Files\Zulu\zulu-21'
$env:GRADLE_USER_HOME = 'C:\Users\USER\.gradle'
.\gradlew.bat :app:assembleDebug --offline --no-daemon --max-workers=1 --console=plain
```

先验证路径和缓存是否可用；沙箱/权限/下载失败按当前工具规则处理，不无休止重试、不借机清理用户缓存。不要把Gradle退出码当唯一通过依据，要检查BUILD SUCCESSFUL/实际失败日志。

分别记录源码构建、JVM测试、迁移/模拟器、真机、云端API结果。旧P2-7帧率/启动采样已经收口，不再反复折腾旧设备。新功能若必需设备或付费端点验收，先把代码、离线用例与步骤准备好；缺少条件时明确标待验证，不捏造结果、不将先前构建次数当本轮证据。
