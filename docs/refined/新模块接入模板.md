# Zero 新模块接入模板

> 适用：本轮（稳定基建与自迭代升级）起新增模块。既有模块继续按 `IZeroModule` 直接实现，不需一次修改。定义见 `【迭代开发设计】多模态核心与框架收敛.md` §2.1 与 `【迭代落地计划】…` §2 F1。

## 最小接入路径（F1 起）

一个新模块 = 继承 `ModuleDescriptor`（省空实现）+ 实现 `ToolContributor`（声明式工具）+ Hilt `@IntoSet` 绑定。

```kotlin
// services/src/main/java/com/zero/v2/services/weather/WeatherModule.kt
package com.zero.v2.services.weather

import com.zero.v2.core.common.ActionPermission
import com.zero.v2.core.common.FunctionDefinition
import com.zero.v2.core.moduleapi.ModuleCategory
import com.zero.v2.core.moduleapi.ModuleConfigBase
import com.zero.v2.core.moduleapi.ModuleDescriptor
import com.zero.v2.core.moduleapi.ModuleMetadata
import com.zero.v2.core.modulemanager.FunctionResult
import com.zero.v2.core.modulemanager.ToolContribution
import com.zero.v2.core.modulemanager.ToolContributor
import javax.inject.Inject
import javax.inject.Singleton

@Singleton
class WeatherModule @Inject constructor(
    private val credentialStore: com.zero.v2.services.security.CredentialStore,
) : ModuleDescriptor(), ToolContributor {

    override val metadata = ModuleMetadata(
        id = "weather",                 // 小写+下划线，[a-z][a-z0-9_]{0,39}
        displayName = "天气",
        description = "查询城市天气",
        category = ModuleCategory.SYSTEM,
    )
    override val requiredPermissions = emptyList<String>()
    override val config = object : ModuleConfigBase() {
        override fun toJson() = "{}"
        override fun fromJson(json: String) {}
        override fun defaultConfig() = this
    }

    // 声明式工具——由 FunctionRegistryModule.registerContributions 统一读取注册
    override fun contributions() = listOf(
        ToolContribution(
            definition = FunctionDefinition(
                name = "weather_query",            // [A-Za-z][A-Za-z0-9_-]{0,63}
                description = "查询指定城市天气",
                parameters = mapOf(
                    "type" to "object",
                    "properties" to mapOf("city" to mapOf("type" to "string")),
                    "required" to listOf("city"),
                ),
            ),
            permission = ActionPermission.AUTO,    // 必填：显式声明，即使默认放行
            noArgs = false,                        // 无参工具设 true，允许空 schema
            handler = { args ->
                val city = args["city"]?.toString() ?: ""
                // …调用真实能力…
                FunctionResult.success("weather:$city:晴")
            },
        ),
    )
}
```

```kotlin
// app/src/main/java/com/zero/v2/app/di/AppBindingModule.kt（追加一行）
@Binds @IntoSet abstract fun bindWeather(m: com.zero.v2.services.weather.WeatherModule): IZeroModule
```

## 接入检查清单

| 项 | 要求 | 校验位置 |
|---|---|---|
| 模块 ID | `[a-z][a-z0-9_]{0,39}`，不重复 | `RegistrationValidator.validateModules`（启动） |
| FC name | `[A-Za-z][A-Za-z0-9_-]{0,63}`，不重复，来源模块已注册 | `RegistrationValidator.validateFunctions` |
| 权限声明 | `ToolContribution.permission` 必填（结构强制） | `ToolContribution` 构造 |
| 参数 schema | 有参工具 `parameters` 非空；无参工具 `noArgs=true` | `RegistrationValidator.validateToolContributors` |
| Hilt 绑定 | `@Binds @IntoSet` 注入 `Set<IZeroModule>` | `AppBindingModule` |
| 生命周期 | 由 `ModuleLifecycleManager.safeCall` 驱动；不自行启停 | `ModuleLifecycleManager.initializeAll` |
| 工具执行 | 经统一 `ToolDispatcher`；权限/参数校验在执行端 | `FunctionRegistryModule.execute` |

## 何时不用 ToolContributor

- 静态工具实现 module-api 的 `ToolContributor`，生命周期管理器在 onAwake 后集中注册；运行时探活后增减的动态工具注入 `ToolRegistrar` 刷新。旧 `registerFunctions()` 生命周期入口已删除。
- Z1 收口后，主动注册残留将被删除，统一走声明式。

## 偏移与后续

- `ToolContributor` / `ToolContribution` 当前位于 `core:module-manager`（因 `FunctionResult` 定义于此）；F2 将 `FunctionResult` 抽至 `core:common` 后，本 seam 迁入 `core:module-api`，与新模块接入路径无影响。
- `ModuleDescriptor` 在 `core:module-api`，纯生命周期默认，不含函数类型。
- 样板单测：`core/module-manager/src/test/.../ToolContributorTest.kt`。
