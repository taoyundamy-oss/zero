## P2 后续执行手册（Luna 开发交接）

> 适用角色：后续由 Luna 按本节逐项落地。每次只完成一个编号纵切片；修改前读取本节、对应现状和 `PROJECT_DESIGN_CURRENT.md` §13，修改后更新本文件。不得把“设计完成”“任务可运行”写成“功能已验证”。

### 通用执行契约

1. **真相入口**：当前代码、`PROJECT_DESIGN_CURRENT.md` 与本进度文档共同构成现状；旧 Roadmap/专项文档只能提供历史线索，冲突时不得覆盖当前裁决。
2. **范围约束**：zero-cloud 已 retired；不得新增、修复或依赖其 compose/Python/profile。P2-8 只记录 retired 边界。本地 Termux supervisor/文件传输/动态模块链路是回归重点。
3. **单步闭环**：每个纵切片按“事实盘点 → 最小实现 → 专项验证 → `:app:assembleDebug` → 更新进度”闭环。失败时保留未完成状态和原始失败点，不用 baseline、全局 suppression 或降低规则掩盖新增问题。
4. **统一验证环境**：Windows 使用 JDK 21，`GRADLE_USER_HOME=D:\ZeroV2\.gradle`、`ANDROID_USER_HOME=D:\ZeroV2\.android`；默认命令为 `gradlew.bat <tasks> --no-daemon --max-workers=1 --console=plain`。阶段收口必须运行 `qualityCheck --no-parallel`。
5. **Seam 纪律**：只有存在真实变化或多个调用方时才建立 seam。Interface 必须隐藏策略复杂度，测试与调用方使用同一 Interface；禁止为迁移而增加只做转发的浅 Module。
6. **变更安全**：保留工作区既有修改；禁止全库自动格式化。Sherpa 二进制、Room schema、Termux 协议或 Trace schema 发生变化时，必须同步校验材料和兼容说明。
7. **停步条件**：需要猜测第三方二进制来源/许可证、需要改变数据库兼容语义、需要真机性能数据却无设备、或需要扩大到 zero-cloud 时，停止该纵切片并记录“待用户/设备证据”，不得自行宣称完成。
