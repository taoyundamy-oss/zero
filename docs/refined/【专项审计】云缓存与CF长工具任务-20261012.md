## 范围与结论

沿生产链审查：ChatBot 回合/工具循环 → 请求视图与世代压缩 → LLM profile/模型契约 → Responses 编解码 → usage/缓存诊断 → UI 统计；不是全仓所有功能的新一轮安全认证。本轮审计与方案交付，不改生产代码、不安装APK、不更改用户模型选择、不调用付费模型、不重试热资源。449项既有工作树改动保留。

结论：存在可确定的缓存连续性缺陷和 Responses 错误诊断缺陷；实机 GPT 中等思考搭配4096总输出预算有耗尽风险。不能由截图直接确定每次失败的服务端原因，也不能将65–93%全部归因于单一缺陷。历史98%用例与真实工具任务的测试口径不同，当前云缓存门仍未通过。

## 已确认发现

### F1 / P1：世代切换生成的工具瘦身视图没有冻结

- `framework/chat/src/main/java/com/zero/v2/framework/chat/ContextWindow.kt:62` 在保留窗口前半段对工具结果生成缩短后的copy。
- `framework/chat/src/main/java/com/zero/v2/framework/chat/ChatBotModule.kt:646` 后续从原始base按起点取消息；665只保存generationStartMessageId，685返回临时slice.messages。
- 因果链：切换请求发送缩短结果 → 下一次用原始base重建 → 若低于90%阈值，直接返回未缩短结果；若仍高于阈值，可能再次切换并重新按位置瘦身。已经发出的消息内容不能保证逐轮不变。
- 影响：包含长工具结果并触发换代的任务，前缀复用和预算稳定性均受损。普通短对话不一定触发。代码路径已确认；本轮未采到用户失败请求完整载荷，不能量化其对65–93%的贡献。

### F2 / P1：世代起点仅存内存，恢复后请求基线重建

- ChatBotModule.kt:113为volatile字段，732加载会话时清空；只有摘要压缩另有持久化，并未恢复此请求世代的完整视图。
- 冷启动/切换会话后可能从完整历史重新切片，与此前缓存基线不同。Android重启本身不必然清除云缓存，但客户端重建的内容可能失去匹配。
- 修复须持久化按会话/模型契约隔离的世代描述及不可变投影视图，不修改用户原始历史；切换配置、编辑历史时显式创建新世代。

### F3 / P1：Responses终止原因被压扁，工具任务直接结束

- `services/src/main/java/com/zero/v2/services/llm/ResponsesStream.kt:25` 将response.failed、response.incomplete和流内error统一转为ResponsesFailure。
- `ResponsesFailure.kt:8` 仅保留usage，丢弃status、incomplete_details.reason、error.code和response标识；顶层error连response对象也没有。
- ChatBotModule.kt:569附近把异常统一转CHAT_REQUEST_FAILED，结束当前循环。没有区分预算耗尽、服务端故障和可恢复中断。
- 用户看到该精确错误可对应上述终止处理，不能把它直接解释成36秒网络超时。共享HTTP readTimeout是120秒；截图的约36秒不是此超时的证据。
- CF绿色行与缺失usage不足以证明生成完整成功，也不能确定请求之间的调用归属。后续255/328token小请求不能未经trace关联就认定为重试。
- 当前只在completed时释放工具调用，这是需要保留的保护，不能为了续跑执行不完整参数。

### F4 / P1风险：真实 GPT 输出预算仅4096，包含思考消耗

只读实机zero_llm_profiles.xml，并按LlmProfileStore优先snapshot_json确认当前配置：openai/gpt-6-luna，cf-luna-responses-v1，enabled=true，effort=medium，maxTokens=4096，maxOutputTokens=32768，contextWindow=1050000。本地Qwen当前disabled；保留用户的当前选择。旧profiles_json仅迁移备份，不能与snapshot混算。

`ModelContract.kt:53` 将maxTokens直接写入max_output_tokens；maxOutputTokens=32768只是配置允许上限，并不是实际发送预算。官方契约规定max_output_tokens包含思考、可见输出及其他生成开销，耗尽会incomplete，甚至无正文。故4096可能够简单聊天，不够复杂工具续轮；这与现象相符，但尚无失败原始reason，属于高可信候选而非已证实的历史触发原因。

另：通用cf-openai-responses-v1的bounded()清空effort，chatBounded又限128token，可能依赖服务端默认思考而耗尽。当前Luna专用契约bounded显式none，不能将此旁支误认本机主故障。

### F5 / P2：缺失缓存观测被默认成0，诊断不覆盖跨进程

ResponsesStream/ResponsesFailure中cached_tokens缺失默认0；TokenUsage不能区分unknown与真实零命中。失败usage虽会计费累计，但失败分支没有正常llm_call_done缓存摘要。CacheRequestDiagnostics只存内存中8条stream哈希，按profile和首消息ID索引；换代/进程重启会断开比较。它比较消息数而不是token前缀长度，不能据此声称命中率。

UI按累计cached/input计算比例是合理的token加权形式，但应同时报告观测覆盖率、provider/模型/会话分组以及冷启动/换代事件；unknown不能直接计作已观测miss。

### F6 / 验收缺口：原98%不代表生产端到端

CacheHitRealProviderTest直接构造DeepSeek固定STABLE_PREFIX，四个短用户问句，热组排除首轮。它不经生产ChatBot的世代压缩，不验证长工具结果、进程重启、CF Responses或混合后台调用。该测试仍可证明自身限定的provider热缓存行为，不能据此宣称日常所有请求98%。

新工具结果属于首次输入，本身需要冷计算。例如已有100k前缀新增10k，单纯复用旧前缀时约90.9%；合理新增量和客户端前缀破坏必须分别统计。不要填充无用长前缀刷比例，也不能删除失败样本。

## 需补证的候选因素

1. TokenBudgetAllocator.kt:102按opaque reasoning的序列化字符估算token，属保守wire估算，可能让换代早于实际provider预算；需将估算与真实input usage配对校准，不能直接当作tokenizer结果或简单删掉加密推理。
2. 工具结果当前可整段进入历史，单个超大工具组为保留调用配对可超过目标预算。应在首次入模前分页/有界摘要，完整结果另存引用；入模后不再滚动改写。
3. 最终无工具综合轮移除tools是请求结构变化，应单列，不能用普通工具热轮门衡量。
4. 服务端缓存保留/路由及CF透传差异需要真实请求级usage和request ID验证；本轮没有CF账户原始响应访问证据，不假定已查明服务端故障。

- 验收：换代首请求→下一工具轮→下一用户轮→重启后的序列前缀一致；工具配对完整、输入+输出预留不超过上限；阈值附近不能来回切片。

- 大结果优化先测量重复与无关传输；确有收益时提供可展开摘要、分页和原文引用，模型可继续读取完整内容。小结果原样保留，避免固定500字符截断成为新的通用方案；同时核对额外往返延迟和任务完整性。
- 原生推理状态与工具调用配对保持完整。缓存稳定以真实内容为基础，不填充长前缀刷比例、不通过漏计失败/unknown或删掉低命中样本达标。

### 建议的最小架构

- 新建独立Android/Hilt账号接入模块（建议名chatgpt_auth），负责登录/退出、受保护凭据、续期及账号状态；通过小接口提供凭据句柄和状态，业务层不读令牌。无需为此引入Codex app-server或第二个Agent执行器。
- 提供ChatGptPlanLanguageModel实现ILanguageModel，注册到现有ModelSelector；保留其能力、enabled、priority和上下文选择规则。现有ProfileLanguageModel在snapshotForTurn冻结凭据，新实现应冻结账号/模型身份，同时允许同一身份的令牌在请求前续期。并发续期合并，退出或切号时迟到续期不能复活旧账号。
- 独立Responses契约适配官方套餐路由；复用经验证的流终态、工具执行、历史和usage基础设施。同步接口可聚合SSE；禁用该路由不支持的参数应限定到该契约，不影响CF/DeepSeek/Qwen。不能直接将OAuth令牌保存为现有API Key来宣称完成。
- 账号/注册/连接/模型参与原生状态及缓存隔离；同账号刷新令牌不改变稳定提示词或历史。授权凭据仅发往官方目的端，不能随现有CF baseUrl或跨域重定向转发。新增存储不复用可能明文回退的路径，备份不导出刷新令牌。
- 设置入口归入现有模型管理，连接后由用户选择启用/优先级；保留当前CF GPT选择。额度不足、未授权及退出状态明确呈现，不擅自切到付费API。套餐额度与现有API费用分列，usage缺失保留unknown；不宣称无限调用或98%缓存。
