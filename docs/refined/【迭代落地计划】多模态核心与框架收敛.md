# Zero v2 迭代落地计划：编程 Agent 执行清单

> 2026-09-30 修订 v2。**执行顺序以《【迭代总纲】稳定基建·系统感知·受控自迭代·UI重构.md》§9 为准**，本文 F/M/C/R/P/I 编号仍是专项任务定义。新增基线清理 B、系统感知 S、Termux 自迭代 E、UI U 和最终退役 Z。框架完整收口是本轮验收条件，不允许只保留接口外壳和旧新双轨。每次仅实现一个编号纵切片，编译通过、记录证据、更新清单，再进入下一片。

## 0. 开工协议

1. 读取 `AGENTS.md`、`ARCHITECTURE_FINAL.md`、`ROADMAP.md`，然后以当前源码、`PROJECT_DESIGN_CURRENT.md` 与本轮设计核对；冲突记入“实施偏移”，不要无声套用旧文档。
2. `git status --short` 留快照；当前工作树含大量用户/前序改动，禁止 reset、clean、覆盖和批量格式化。每片只碰列明文件及必要测试/DI/迁移。
3. 一片一提交（若用户/仓库工作流允许），提交前至少 `:app:assembleDebug` 或影响到的子项目编译、相关 JVM 单测。数据迁移片还跑迁移 instrumentation 或等价设备证据。不能把编译、模拟器、真机、云端 API 验证混写。
4. 每片留 `变更文件/行为差异/验证命令与结果/未验证边界/回退开关/下一片`。旧功能与权限守卫是回归基线。先跑离线测试；只有明确需要时再调用真实付费模型。
5. 不增量引进大文件本地模型，不新建跨设备服务，不重启 P2-7 性能采样；设备性能验收等代码就绪后另起可复现实验。

## 1. 总览与依赖

```text
F1 模块样板/注册校验 ── F2 窄契约与依赖方向
                        ├── M1 内容块/附件持久引用 ── M2 能力路由 ── M3 Provider 原生输入 ── M4 回退/工具媒体
                        ├── C1 PromptPlan/前缀观测 ── C2 历史/证据/工具预算 ── C3 98% 实测
                        ├── R1 记忆持久作业 ── R2 有界检索 ── R3 自动证据注入/引用
                        └── P1 角色状态存储 ── P2 Reducer ── P3 风格/UI
所有主线 ── I1 集成回归/文档收口
```

实施优先级：F1 → F2 → C1 → M1 → M2 → M3 → C2 → R1 → R2 → R3 → P1 → P2 → P3 → M4 → C3 → I1。允许根据测试反馈调整，但每片的依赖和验收不能跳过。F1/F2 不要求全仓接口重构。

## 2. 纵切片清单

### F1 模块快捷接入

- [ ] 设计 `ModuleDescriptor` 与可选 `ToolContributor`，为现有模块提供不破坏 ABI 的默认适配；给新模块提供最小样板（metadata、config、生命周期、函数权限、错误处理、Hilt `@IntoSet`）。
- 主要文件：`core/module-api/IZeroModule.kt` 邻近新文件，`core/module-manager/RegistrationValidator.kt`，`app/di/AppBindingModule.kt`；新增 `docs/refined/新模块接入模板.md`。
- 验收：注册缺失 ID/重复 ID、函数名重复、无权限声明、无 schema 被拒绝；样板模块在单测中完成生命周期与目录发现；既有模块不需一次修改。

### F2 调用边界和依赖方向

- [ ] 只抽取当前 Chat/Services 之间真实共用的 `ModelRouter`、`PromptComposer`、`EvidenceProvider` 契约；调用者改为依赖接口，由 Hilt 提供实现。减少直接 concrete 注入；每次调整 Gradle 依赖前画出该次实际 import 图。
- 验收：无新循环依赖；ModuleLifecycleManager.safeCall、ToolDispatcher 统一执行入口不被绕过；旧行为契约测试通过。若 `services → module-manager` 暂不能移除，记录残余引用与后续门槛，不为追求图好看横向重写。

### C1 稳定前缀与观测

- [ ] 新建 `PromptPlan`：固定 persona/协议组成 stable system，摘要/动态信息进入本轮 context。provider 请求序列化固定字段顺序和工具排序；计算 `prefixVersion`。`OpenAiCompatibleClient` 解析 cache hit/miss usage 并携带到 trace 聚合。
- 主要文件：`framework/chat/ContextBuilderModule.kt`、`ChatBotModule.kt`、`services/llm/OpenAiCompatibleClient.kt`、usage DTO；不在 Trace 记录原 prompt。
- 验收：相同 persona/profile/工具 manifest 连续轮 stablePrefix 字节相同；摘要更新、时间变化、情绪变化不改变 hash；角色/profile/工具 manifest 变更会改变 hash；缺 usage 显示 unknown 而非 0%。

### M1 内容块与媒体引用

- [ ] 在 `core:common` 增加版本化 `ContentPart` 和 ChatMessage 旧内容适配；附件仍保存元信息，但单次调用能按引用读取内容。若新增 Room 附件表，按当前 v22 加 v22→v23 migration、schema 导出和旧库数据保留测试。
- 验收：文本、单图、多图、不可用 URI、超尺寸图片、取消中途、进程重启后的附件可用性都有确定结果；base64 不写数据库/日志；原正文不被视觉描述悄然改写。

### M2 模型能力路由

- [ ] `LlmProfile` 增加经用户/预置验证的能力字段与协议方言；旧 profile migration 默认按已知能力保守填充。`ModelSelector` 用 `ModelRequirements` 筛选，再按用户优先级/可用性/确定性 tie-break 选择；不把 CHAT 等同 IMAGE_INPUT。
- 验收：纯文本仍能选已有 DeepSeek/Qwen；图像选明确支持原生图的 profile；缺能力解释为何回退；禁用/缺 Key 不入候选；不因 modelId 字符串包含“vl”自动声明能力。

### M3 原生多模态请求

- [ ] Provider codec 对明确支持的兼容端点生成内容数组；先覆盖图片，音频接口留扩展位并只对实际支持 provider 启用。全路径保留流式文本、tool call、reasoning/usage 解析。
- 验收：请求快照覆盖纯文本、单图、多图、工具轮、媒体上传失败；有配置的真实端点小样本验证另列 E2，不以 mock 测试宣称线上可用。云端协议差异在 codec 内，不在 ChatBot 到处 `if(provider)`。

### C2 上下文与工具预算

- [ ] `TokenBudgetAllocator` 接入模型预算、输出预留及安全余量；历史摘要按 `summary_upto` 替换旧段；Memory/KB/风格统一放本轮短 context。工具从默认全量改为基础集合+top K+发现入口，首期灰度开关保留旧目录。
- 验收：长历史+多工具+图像下请求不超模型预算；工具 JSON schema 不被截坏；明确命名工具可见；无意图匹配不会把全量工具塞入请求；旧工具调用权限和参数校验不变。

### R1 记忆提取作业持久化

- [ ] 用 Room outbox/job 替代 `pendingAiBuffer` 易失队列，单回合唯一键、任务状态、尝试次数、来源 ID/水印和有界保留。提取只接受可复核文本事实/偏好，图/音频转写仅作为候选来源。
- 验收：进程退出后续跑不重复写；失败退避、取消/删除级联清理；AI 臆测、角色扮演与临时情绪不入长期记忆；迁移旧库成功。保留现有 Memory/UserGraph 语义。

### R2 有界中文混合检索

- [ ] Memory/KB DAO 增加按状态/模型/时间/词法的有界候选查询；统一 `EvidenceRef`、RRF/去重实现，不把各自写入域合并。维度和模型不匹配走中文词法降级。
- 验收：100/1k/10k 条样本上的 P50/P95、峰值内存和召回对比旧全表余弦；默认候选上限有测试；索引失效/重建可恢复；不依赖普通 FTS5 中文分词假设。
- 后续决策门槛：只有 10k 样本仍不达设备预算，才独立评估 sqlite-vec/倒排索引，并完成 Android ABI/Room/迁移 spike；不得直接导入主干。

### R3 自动证据注入

- [ ] 回合入口并行询问 Memory/Knowledge 的 EvidenceProvider，按分数与预算选 ≤3 条短证据，附来源；用户可分别关掉自动注入。低分不注入，证据正文不写 Trace。
- 验收：不相关问题空注入；明确用户偏好、文档事实分别可回链；关开关不删除数据；旧摘要/知识 chunk/用户图谱不互相冒充；RAG 变化不扰动 stablePrefix。

### P1 动态角色存储

- [ ] `CharacterRelationState` 按角色，`ConversationMoodState` 按会话；带事件/幂等键、revision、更新时间。当前 Room 版本递增一阶（若 M1 已升至 v23，则此处 v23→v24，禁止重复占用版本）；事务写入、schema 导出与迁移测试。
- 验收：旧角色和旧会话默认中性；切换角色不串值；角色删除清理状态；无动态记录仍用原固定 systemPrompt。

### P2 状态 Reducer

- [ ] 纯规则 `CharacterStateReducer` 先行：状态枚举、限速、衰减、无关回合不变、单回合幂等；若使用云端模型仅生成候选事件，最终规则裁决由本地确定性代码执行，失败不影响回复。
- 验收：重复回合、取消回合、负面语句、用户显式重置、跨会话亲密度、会话情绪 TTL 的契约测试；状态不影响工具权限和事实判断。

### P3 风格与 UI

- [ ] 角色页展示亲密度档位、当前会话情绪、变化依据与更新时间；提供动态表达开关、分别重置。`PromptPlan.turnContext` 中合成 ≤120 token 短风格指令；固定 systemPrompt 不改写。
- 验收：用户能查看和重置，重置后 prompt 下轮生效；状态变化不改 prefixVersion；关动态表达仍可保留/查看数据；无障碍读屏可用。

### M4 回退与工具媒体结果

- [ ] 原生图/音频不支持或允许的暂时失败才回退 Vision/ASR；`FunctionResult` 新增可选媒体引用前先约定大小、保留期、授权和旧文本调用方投影。
- 验收：错误分类、回退路径、工具二进制拒绝/限额、附件授权过期可见；媒体不会作为无界 base64 进入 system/tool 文本。

### C3 缓存热请求验证

- [ ] 在已有用户授权的真实 provider 做固定 persona/model/工具 manifest 的连续热请求，比较 system/工具序列化字节与 provider usage。按设计文档 D2 指标报 P50/P10、样本数、未观测数、首轮/切换 cohort、总输入 cached 占比和失配原因。
- 验收：满足设计§4.2的cohort token加权比率≥98%，同时披露覆盖率/失败/服务端失效，才报告该可观测样本“目标达到”；仅有估算token时标为估算，不能说精确测得。成本/用量上限预先设定。无需重新开展P2-7帧率/启动采样。

### I1 集成与现状同步

- [ ] 跑受影响子项目测试、`:app:assembleDebug` 与 `qualityCheck`；Room 迁移另报设备/instrumentation 证据；更新 `PROJECT_DESIGN_CURRENT.md` 当前事实、进度文档新增本轮入口链接和剩余边界。检查所有 feature flag 默认与回退。
- 验收：文档中“设计”“代码已实现”“模拟器”“真机”“云端 API”分栏，任何未跑项标待验证；不改写 P2-7 既有证据。
